# Project 1 -- FYS-STK4155

Regression on the Runge function using OLS, Ridge, and LASSO with univariate
polynomial design matrices, fit via both closed-form solutions and gradient-based
optimization (GD, SGD, momentum, AdaGrad, RMSProp, Adam), and evaluated with
bootstrap and cross-validation resampling. Coursework for FYS-STK4155 at UiO.

The report is [`docs/main.pdf`](docs/main.pdf), built from LaTeX source in
`docs/` against numerical results regenerated by `scripts/` — see
[Reproducing the report](#reproducing-the-report).

## Project structure

```
.
├── src/fys_stk4155_p1/   # importable package — all reusable logic lives here
│   ├── data/             # Runge sampling + polynomial design matrices
│   ├── regression/       # OLS, Ridge, LASSO (closed-form + gradient descent)
│   ├── optimization/     # optimizers (GD, SGD, Momentum, AdaGrad, RMSProp, Adam)
│   └── resampling/       # bootstrap, cross-validation
├── tests/                # pytest test suite, mirrors src/ structure
├── scripts/              # thin runnable entry points: data, experiments, figures
├── notebooks/            # exploratory Jupyter notebooks (outputs stripped on commit)
├── data/                 # raw data (gitignored) + versioned experiment results
├── docs/                 # IEEE-format LaTeX report, compiled PDF, figures
└── .github/workflows/    # CI: pre-commit hooks + tests on every push/PR
```

## Setup

Requires [uv](https://docs.astral.sh/uv/) and Python 3.12 (pinned in
`.python-version`).

```bash
uv sync                  # installs dependencies + dev tools into .venv
uv run pre-commit install  # enable git hooks (lint, format, nbstripout, mypy, gitleaks)
```

## Development

```bash
make test         # uv run pytest (with coverage)
make lint         # uv run ruff check .
make format       # uv run ruff format .
make typecheck    # uv run mypy
make check        # lint + typecheck + test
```

CI (`.github/workflows/ci.yml`) runs the same checks on every push to `main`
and every pull request.

## Reproducing the report

Every number and figure in the report is derived from the same
config-driven pipeline, so it can be rebuilt from a single command:

```bash
make report     # -> docs/main.pdf
```

which chains:

```bash
make experiments    # run numerical experiments, write JSON to data/results/
make figures        # regenerate all report figures/tables into docs/figures/
```

All experiment settings (sample size, noise, polynomial degrees, CV folds,
penalty grids, seeds) live in one place, `scripts/utils/config.py`; changing
a value there and re-running `make report` keeps every number and figure in
the report consistent. `e2` (model selection) is the slow step, about 1
CPU-hour, parallelized over data seeds — see `scripts/README.md`.

## Reproducibility

- Dependencies are pinned via `uv.lock`; always use `uv run`/`uv sync`
  rather than an ad hoc environment.
- Set and log random seeds explicitly wherever randomness is involved
  (train/test splits, weight init, bootstrapping) — don't rely on global
  state.
- Notebooks are for exploration only; code meant to produce a reported
  result belongs in `src/` (tested) and is invoked from a script, so the
  result can be regenerated deterministically from a single command.
- Raw data is never committed — `data/README.md` documents how to (re)obtain
  it. Selected experiment results *are* versioned under `data/results/`
  (course requirement) so the reported numbers are visible without rerunning
  anything; `data/results/SUMMARY.md` indexes them.
- Use of LLM tools is disclosed per-file (`LLM-assisted` docstring tags) and
  summarized in the report's appendix (`docs/sections/appendices/0a-ai-usage.tex`),
  per the course's LLM usage guidelines.
