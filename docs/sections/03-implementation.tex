\section{Implementation}
\label{sec:implementation}

All methods are implemented in a Python package built on
NumPy~\cite{harris_2020}; the source code, the tests, the
experiment scripts and the results behind every number in this report are in
the project repository~\cite{riseth_2026}. This section
describes the data, the preprocessing, the structure of the code, and how we
verified it.

\subsection{Data and preprocessing}
\label{subsec:data}

We draw $n = 100$ inputs uniformly from $[-1,1]$, evaluate Runge's function
\cref{eq:runges_function}, and add i.i.d.\ Gaussian noise with $\sigma = 0.1$
(\cref{eq:data_generating_process}). The data are split
80/20 into a training and a test set. Unless stated otherwise, all results use
this reference data set (seed 42). The statistics in
\cref{subsec:results-selection} repeat the whole pipeline on 31 independent data
sets. All settings are defined in one configuration file,
from which every figure and table is regenerated by a single command
(\texttt{make figures}).

The design matrix has the columns $\bm{x}, \dots, \bm{x}^p$; it carries no all-ones
intercept column. We standardize every column to zero mean and unit
variance, using means and standard deviations computed on the training rows
only (scikit-learn's \texttt{StandardScaler}~\cite{pedregosa_2011}), and
apply the same transformation to the test rows. Inside cross-validation, the
scaler is part of a \texttt{Pipeline}, so it is refitted on the training folds
of every split. This matters because a scaler fitted on all rows would use the
mean and variance of the held-out fold, so the validation points would no
longer be unseen data and the CV estimate would be biased; with $n=100$ the
effect is small, but the same holds for any preprocessing learned from the
data. We scale for three reasons. First, the raw columns $\bm{x}^j$ have
very different magnitudes on $[-1,1]$, and the penalties of Ridge and Lasso
would then shrink the coefficients of the small columns much more than those of
the large ones; after standardization, $\lambda$ acts on all coefficients on
the same footing~\cite{hjorth-jensen_2026,geron_2023}. Second, standardization improves the
conditioning of $\bm{X}^\top\bm{X}$, which sets the speed of gradient descent
(\cref{eq:gd_stability}). Third, every model fits its intercept by centering
$\bm{y}$ on its training mean instead of through a column of $\bm{X}$; since
the standardized columns are centered, this is exactly equivalent to a joint
fit with a free, unpenalized intercept. For $\bm{X}$ of full column rank, OLS
predictions do not depend on the scaling (it is an invertible linear
reparametrization of the same model); Ridge, Lasso and every gradient method
do. The target itself is
never scaled, only centered internally by the model.

\subsection{Code structure}

The package \texttt{fys\_stk4155\_p1} contains four subpackages: \texttt{data}
(sampling of Runge's function and the design matrix), \texttt{regression} (the
models, costs and gradients), \texttt{optimization} (the update rules and
learning-rate schedules), and \texttt{resampling} (the bootstrap and $k$-fold
CV). Thin scripts combine them into the experiments and figures.

All models inherit from a common estimator class that follows the scikit-learn
convention, so they can be used directly in scikit-learn's
\texttt{Pipeline}, \texttt{KFold} and \texttt{cross\_validate}. \texttt{OLS}
solves the least-squares problem through the SVD-based pseudoinverse
\cref{eq:ols-pseudoinverse} with a relative singular-value cutoff of machine
precision times $\max(n,p)$. \texttt{Ridge} solves the normal equations
\cref{eq:ridge-theta-hat} with \texttt{numpy.linalg.solve}; the penalty makes the
system well-posed for $\lambda>0$. \texttt{GradientDescent} minimizes the
OLS/Ridge (or Lasso) cost with any of the update rules plain, momentum,
AdaGrad, RMSprop and Adam, full-batch or with mini-batches, using either the
analytical gradient or the gradient from automatic differentiation with
JAX~\cite{bradbury_2018} (in double precision).
\texttt{Lasso} minimizes the Lasso cost with the same code, using the
subgradient \cref{eq:lasso_subgradient} in place of the gradient; unless stated
otherwise we use Adam with $\gamma = 0.05$ and 5000 iterations. All solvers
follow \cref{alg:gd}.

\begin{algorithm}
    \caption{Gradient descent with a generic update rule}
    \label{alg:gd}
    {\small
    \begin{algorithmic}[1]
        \Require $\bm{\theta}^{(0)}$, schedule $\gamma_t$, batch size $M$
        ($M = n_\text{tr}$: full batch), epochs $E$, tolerance $\tau$,
        update rule $\mathcal{U}$ with state $\bm{s}$
        \State $t \gets 0$, $\bm{s} \gets \bm{0}$
        \For{$e = 1, \dots, E$}
            \State Shuffle the training rows; split into $\lceil n_\text{tr}/M\rceil$ batches
            \For{each batch $\mathcal{B}$}
                \State $\bm{g} \gets \frac{1}{|\mathcal{B}|}\sum_{i\in\mathcal{B}}
                \nabla_{\bm{\theta}} c_i(\bm{\theta}^{(t)})$ \Comment{analytical or JAX}
                \If{$M = n_\text{tr}$ \textbf{and} $\lVert\bm{g}\rVert_\infty < \tau$}
                    \State \Return $\bm{\theta}^{(t)}$
                \EndIf
                \State $(\bm{\theta}^{(t+1)}, \bm{s}) \gets
                \mathcal{U}(\bm{\theta}^{(t)}, \bm{g}, \gamma_t, \bm{s})$
                \Comment{e.g.\ \cref{eq:gd_basic,eq:adam-iterate}}
                \State $t \gets t + 1$
            \EndFor
        \EndFor
        \State \Return $\bm{\theta}^{(t)}$
    \end{algorithmic}
    }
\end{algorithm}

Every function that involves
randomness takes an explicit seed, and all numbers in this report are
regenerated deterministically by \texttt{make experiments}.

\subsection{Verification}
\label{subsec:verification}

The package has a test suite of 164 unit tests, run by continuous integration on every push. The tests
most relevant for trusting the results check the code against closed-form
results and independent implementations:

\begin{itemize}
    \item \textbf{OLS and Ridge:} OLS recovers the coefficients of an exactly
    linear data set; Ridge with $\lambda=0$ equals OLS; the Ridge coefficients
    shrink monotonically in $\lambda$; and the intercept is not penalized.
    \item \textbf{Gradients:} the analytical gradients agree with those from
    JAX to a maximum relative difference of $1.0\times10^{-15}$ over 100 random
    $\bm{\theta}$ at degrees 5, 10 and 15, for OLS, Ridge and Lasso away from
    $\theta_j = 0$; at $\theta_j=0$ they differ by exactly $\lambda$
    (\cref{subsec:gradient-descent}).
    \item \textbf{Gradient descent vs.\ closed form:} with $\gamma=1/\lambda_{\max}$, plain GD
    converges linearly to the closed-form OLS and Ridge solutions
    (\cref{fig:gd_convergence}), and the stability boundary
    \cref{eq:gd_stability} is reproduced (\cref{fig:gd_stability}).
    \item \textbf{Optimizers:} each update rule reproduces its formula for
    one step on known inputs, and converges on a quadratic test problem.
    \item \textbf{Lasso:} on a well-conditioned test problem, our
    subgradient solver agrees with scikit-learn's coordinate-descent
    \texttt{Lasso} (with $\alpha = \lambda/2$) to $0.05$ in every coefficient;
    the number of small coefficients grows with $\lambda$; and the intercept is
    not penalized.
    \item \textbf{Resampling:} the bootstrap and CV are deterministic for a
    given seed, and the bias measured against $\bm{y}$ exceeds the bias
    measured against $\bm{f}$ by approximately $\sigma^2$
    (\cref{eq:measured-bias}).
\end{itemize}
